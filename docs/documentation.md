# 文档维护规则

1. **单一真源**：一个事实只在权威文档定义；其他文档链接它，不复制易漂移的
   表格、命令清单或测试数量。
2. **按任务读取**：从 [`README.md`](README.md) 的路由选择最多三个入口，并用
   “目标、范围、入口、最小验证、停止条件”形成一屏任务卡。
3. **契约同步**：ISA、地址、软件 ABI、可观察协议或板级事实变化时，在同一变更
   中更新对应真源、实现和测试。
4. **重大取舍写 ADR**：只有会长期约束替代方案的决定才复制
   [`decisions/template.md`](decisions/template.md) 新建 ADR；Accepted 记录的背景、
   决策与后果不重写，只更新状态、superseded 关系或事实性错误。
5. **实测带证据**：性能、面积、频率、功耗和验证结论必须记录工具、阶段、配置、
   负载、命令与日期；没有证据时写 `TODO` 或“未验证”。
6. **临时内容不反向依赖**：本地草稿区只保留 `.gitignore`，正式资产不得链接或
   依赖其中内容。草稿结晶后由用户确认清理，不自动删除。

正式文档只由四类事件触发更新：外部契约变化、重大方案取舍、难以复现的疑难
根因、昂贵或不可重复的实测证据。内部重命名、等价重构、普通测试补充和短时
语法修复不要求更新。

AI 成本记录是本地、自愿且非阻塞的实验。可记录任务类型、回合或工具次数、耗时、
首次通过与返工时间；至少积累 20 个任务后再决定是否引入模型预设、自动路由、
RAG 或网关，未实测前不宣称固定节省比例。
